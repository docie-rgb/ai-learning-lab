# PRD - 내 Todo(할 일) 앱

## [무엇]
내 컴퓨터에서 도는 Todo(할 일) 앱.
브라우저(`http://localhost:3000`)에서 할 일을 관리하고, 데이터는 DB에 저장돼 새로고침하거나 서버를 껐다 켜도 남는다.

## [기본 기능(CRUD)]
| 기능 | 설명 | API |
|---|---|---|
| 할 일 추가 (Create) | 제목(필수)과 마감일(선택)을 입력해 추가 | `POST /api/todos` |
| 목록 보기 (Read) | 전체 할 일을 마감일이 가까운 순으로 표시 | `GET /api/todos` |
| 완료 표시 (Update) | 체크박스로 완료/미완료 전환 | `PATCH /api/todos/:id` |
| 삭제 (Delete) | 할 일 하나를 삭제 | `DELETE /api/todos/:id` |

## [저장]
- **길 A (로컬):** 내 컴퓨터의 무료 DB인 SQLite 파일 하나(`todo.db`)에 저장한다. Node 내장 `node:sqlite`를 쓴다.
- **길 B (클라우드):** 같은 앱의 저장소를 Supabase(무료 클라우드 Postgres)로 바꾼다.
- 껐다 켜도 할 일이 남아야 한다.

## [내가 넣고 싶은 기능]
1. **마감일 표시**
   - 할 일마다 마감일을 지정할 수 있다(선택).
   - 마감일이 지났는데 완료하지 않은 할 일은 빨간색으로 강조한다.
2. **오늘 할 일만 보기**
   - '전체 / 오늘' 필터로, 마감일이 오늘인 할 일만 볼 수 있다.

## [규칙]
- 무료 도구만 사용한다 (Node.js, Express, SQLite, Supabase Free, Render Free).
- 비밀값(Supabase 접속 키 등)은 `.env`에 두고, 코드는 환경변수 이름으로만 읽는다.
- `.env`와 `todo.db`는 `.gitignore`에 넣어 GitHub에 올리지 않는다.
- **프론트는 백엔드에만 요청하고, 백엔드만 DB에 접근한다.** 화면 코드에 DB 주소나 키를 두지 않는다.
- DB에 값을 넣을 때는 파라미터화 쿼리를 사용한다 (SQL 주입 방어).
- 백엔드에서 입력을 검사한다: 제목은 비어 있으면 안 되고 200자 이하, 마감일은 날짜 형식(YYYY-MM-DD)이어야 한다.
- 로그인은 직접 만들지 않고 검증된 도구(Supabase Auth)를 쓴다 (길 B).

## [길 B 추가 조건 - 클라우드 전환과 보안]
- Supabase Auth로 로그인하고, 할 일마다 소유 사용자(`user_id`)를 기록한다.
- RLS(행 수준 보안)를 켜고, 로그인한 사용자가 **자기 할 일만** 조회·추가·수정·삭제할 수 있도록 정책을 설정한다.
- 확인: 서로 다른 테스트 계정 두 개로, A의 할 일이 B에게 보이지 않고 B가 A의 할 일을 수정·삭제할 수도 없는지 확인한다.
- 백엔드를 Render에 배포해 인터넷 접속 URL로 동작을 확인한다.

## [완료 기준]
- [ ] 브라우저에서 할 일을 추가하면 목록에 뜨고, 새로고침해도, 서버를 재시작해도 남는다 (로컬 / Supabase 각각).
- [ ] 완료 표시와 삭제가 동작한다.
- [ ] DB 뷰어(로컬: SQLite 뷰어 / 클라우드: Supabase Table Editor)에서 `todos` 표에 행이 쌓인 것을 확인한다.
- [ ] 마감일 강조와 '오늘' 필터가 동작한다.
- [ ] 다른 계정의 할 일은 보이지 않고, 수정·삭제 요청도 거절된다 (RLS).
- [ ] Render 배포 URL에서 앱이 동작한다.

## [만들지 않는 것]
- 태그/카테고리, 검색, 할 일 수정(제목 변경), 공유 기능
- 모바일 앱
